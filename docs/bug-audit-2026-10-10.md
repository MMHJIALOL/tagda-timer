# Website bug audit — 10 October 2026

This audit covers the checked-out Tagda Timer website. Eighteen confirmed issues have been fixed locally, including the moving cube/statistics feedback loop, mixed result units, mobile SOTD layout, race submission failures and asynchronous settings reversion. The table records reproduction, cause, correction and regression coverage for each issue. Final verification results are recorded below; this is not a claim that every possible defect has been found.

All reproductions use a local server, disposable browser data, injected service failures or the local Firebase database emulator. No production test data, deployment or publishing is part of this work. Physical-device and live-service gaps are listed explicitly.

## Method and coverage

1. Run existing statistics, data, settings, solver and browser self-tests.
2. Exercise desktop (1280 × 800), tablet (1024 × 768, 820 × 1180, 768 × 1024), phone (640 × 960, 390 × 844, 320 × 568), and landscape phone (844 × 390) layouts.
3. Test timing, penalties, history, stats, sessions, event/trainer changes, reconstruction, Cross + 1, daily scramble, races/1v1, competition, settings and persistence.
4. For each confirmed issue: record reproduction, root cause, fix and regression evidence before closing it.
5. Record limitations explicitly for authenticated multiplayer, real cameras/timers, external integrations and physical touch devices.

### Reproduce locally

Install the repository's existing dependencies with `npm ci`. Have Playwright and the selected browser available; `TAGDA_PLAYWRIGHT_PATH` may point to an existing installation, so the audit does not add a runtime dependency to the website. Start the development server in a separate terminal:

```powershell
python serve.py 5186 --no-browser
```

Then run:

```powershell
$env:TAGDA_PLAYWRIGHT_PATH = 'C:\path\to\node_modules\playwright'
$env:TAGDA_BROWSER = 'chrome' # also firefox, webkit, chromium or msedge
npm run test:site
node --test js/settings-search.check.mjs js/stats-session.check.mjs js/stats-units.check.mjs js/sync-queue.check.mjs js/cube.check.mjs js/stackmat.check.mjs js/data-health.test.js
```

For a focused rerun, use `node tools/verify-site.cjs <section>`. `TAGDA_QA_URL` defaults to `http://localhost:5186` and accepts only localhost/127.0.0.1 origins. The suite blocks project/auth service requests and uses disposable browser storage. Local multiplayer uses two real tabs and the actual local transport. Authenticated SOTD and Firebase failure/path tests use isolated controllers or injected SDK methods.

Results, screenshots and run logs are in ignored `audit-qa/`; they are local evidence rather than shipped website assets. The six `results-<browser>-<section>.json` files contain the latest check results. `diagnostics-*.json` retain expected navigation diagnostics. Exploratory scripts and earlier failed-run logs are retained there for diagnosis; use the latest results when assessing the final patch.

WebKit reports a vendor worker error when a rapid reload cancels the outgoing page's worker request. A lifecycle probe traced it between `beforeunload` and `pagehide`, alongside `Load request cancelled`; four recorded solves, the current custom scramble and the preview restored correctly. The suite separately records only that exact error when the matching worker request was cancelled during an explicit reload. Live-page worker errors and other errors still fail. No application-level error suppression was added.
