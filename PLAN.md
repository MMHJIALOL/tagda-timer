# Tagda Timer — a modern WCA speedcubing timer

> A cstimer replacement that is actually pleasant to look at, with official WCA
> random-state scrambles, real WCA inspection, a static 3D scramble preview, deep stats,
> 3x3 trainers with per-case stats, and a theme engine that lets the user rebuild the entire look.

---

## 0. TL;DR of what gets built

A single-page web app (no backend for v1, everything local-first in IndexedDB) that does:

- **Official WCA scrambles** for all 17 WCA events, generated by the same random-state solvers TNoodle uses.
- **WCA inspection** — 15s, "8 seconds" and "12 seconds" callouts, +2 penalty past 15s, DNF past 17s.
- **Trainer modes** for 3x3: PLL, OLL, 2-look OLL/PLL, OCLL, last layer, cross-solved, last slot, 2-gen and Roux LSE — the case-based ones carry **per-case stats** so you can see which PLL is actually killing you.
- **A static 3D preview** of exactly how the cube will look after the scramble, plus a flat 2D view and a last-layer view for trainers.
- **Full stats**: ao5/ao12/ao50/ao100/ao1000, mo3, best/worst, session mean, PB tracking, trend chart, distribution histogram, GitHub-style solve heatmap, per-case breakdowns.
- **Total UI customization**: theme token editor, custom background (image / video / animated shader / gradient), font choice, timer style, layout toggles, blur and dim controls, import/export theme JSON.
- **A full keyboard layer** — delete, +2, DNF, comment, new scramble, event/mode/session pickers,
  zen mode, fullscreen, and a Ctrl+K command palette. Detailed in §13.
- **A small creator chip** in the corner linking to @cubingngagng — a credit, not an advert.
- **Motion design that is the actual point** — see §6. Not "a number that changes."

## 1. Stack decision (and why)

| Layer | Choice | Why |
|---|---|---|
| Build | **none — plain ES modules** | Node was not installed on the machine, and the app genuinely does not need a bundler. Any static server runs it; deploy is a folder upload. |
| UI | **vanilla JS + TypeScript-style JSDoc** | No framework tax on a single-screen app; the timer loop stays fully under our control. |
| Styling | **hand-written CSS + custom properties** | Every color/radius/font is a CSS variable so the theme editor just rewrites variables at runtime — no rebuild, no re-render. |
| Animation | **CSS transitions + Web Animations API** | Hand-written, so nothing heavy runs during a solve. |
| 3D cube | **cubing.js `<twisty-player>`** | Handles every WCA puzzle, not just cubes — megaminx, clock and square-1 included. |
| Shader background | **raw WebGL fragment shader** on a fullscreen quad | Cheap, gorgeous, pausable. |
| Scrambles | **cubing.js (`cubing/scramble`)**, mirrored into `vendor/` | The officially-derived random-state generator. It already runs its solver in a worker, and the local mirror means the timer works offline. |
| Charts | **hand-rolled SVG** (no chart library) | Full control over animation and theming; chart libs fight the theme engine. |
| Storage | **IndexedDB, hand-rolled wrapper** | Thousands of solves, indexed queries, no 5MB localStorage wall, no dependency. |
| State | **a plain object + IndexedDB** | The app has one screen; a state library would be ceremony. |
| Deploy | Vercel or Netlify (later) | Static output, zero config. |

**No backend in v1.** Accounts and cloud sync are v2 (§10).

## 2. Scrambles

### 2.1 Official WCA events (all 17)

Generated with `randomScrambleForEvent(eventID)` from cubing.js, which uses the same random-state
search that TNoodle (the WCA's official scrambler) uses. Events:

`333` `222` `444` `555` `666` `777` `333bf` `333fm` `333oh` `clock` `minx` `pyram` `skewb` `sq1` `444bf` `555bf` `333mbf`

Event-specific behaviour that must be handled, not glossed over:

- **BLD events (`333bf`, `444bf`, `555bf`)** — no inspection countdown; memo/exec split timing (tap once to mark end of memo).
- **FMC (`333fm`)** — not a speed timer at all: 60-minute countdown, a text area to enter the solution, move counting (HTM), and validation that the solution actually solves the scramble.
- **MBLD (`333mbf`)** — N scrambles at once, cubes-attempted/solved input, WCA points formula.
- **Clock / Square-1 / Megaminx** — multi-line scramble formatting so it does not turn into a wall of text.

### 2.2 The scramble pipeline (this is where most timers go wrong)

Random-state 3x3 scrambles take real CPU time and cubing.js needs a WASM warm-up. So:

1. On app load, spin up a **scramble worker** and warm the solver for the current event.
2. Keep a **queue of 3 pre-generated scrambles** per active event.
3. When the user finishes a solve, the next scramble is already sitting in memory — it appears **instantly**, no spinner, ever.
4. Switching events kicks off a background warm-up while showing the first scramble from a small pre-baked fallback pool.
5. Every scramble is stored **with the solve**, so history is fully reproducible.

### 2.3 Trainer / subset modes (the cstimer feature set, done better)

Two generation strategies, neither of which needs a solver:

**(a) Inverse-algorithm generation** — for case-based trainers (PLL, OLL, 2-look OLL/PLL, OCLL).
Take the case's algorithm, invert it, and wrap it in random AUFs. Fast, exact, and the app
*knows which case it gave you* — which is what makes per-case stats possible.

**(b) Subgroup composition** — for state-based trainers. The trick that avoids needing a solver:
sequences like `R U R'`, `F' U F` and `L' U L` all restore the D layer, so *any* composition of
them leaves the cross solved. Compose a random handful, invert it, and you have a cross-solved
scramble. The same idea with restricted move pools gives 2-gen (`<R,U>`) and Roux LSE (`<M,U>`).

Trainer UI:

- Case picker with a grid of every case, multi-select, "all / none / invert".
- **"My worst 8"** — one click selects the cases you are slowest at.
- Per-case bars in the statistics panel, ranked slowest first.

Shipped 3x3 subsets: `PLL (21)` `OLL (57)` `2-look OLL` `2-look PLL` `OCLL (7)` `Last layer`
`Cross solved` `Last slot + LL` `2-gen (R,U)` `Roux LSE (M,U)` `Roux L10P` `Cross practice`.

**Verified, not assumed:** `test.html` simulates a real cube and checks that all 21 PLL algorithms
and all 57 OLL algorithms produce the correct — and mutually distinct — case, and that the
cross-solved generator really does leave the cross solved. This caught a genuinely wrong Ja perm
during the build.

Deferred to a later pass: ZBLL (493 cases), CMLL, F2L, EOLine, and the 2x2 / Pyraminx sets.

## 3. Timing and inspection

### 3.1 Accuracy

- All timing off `performance.now()` — monotonic, unaffected by clock changes.
- Display driven by `requestAnimationFrame`, **never** `setInterval` (setInterval drifts and stutters).
- The final time is computed from start/stop timestamps, not from accumulated frames, so a dropped frame can never cost you a PB.
- Stored to the millisecond; displayed rounded per WCA (truncate to hundredths).

### 3.2 WCA inspection (exactly as in comps)

- 15 second countdown, starts when you first touch the timer.
- Spoken or tonal callouts at **8 seconds** and **12 seconds** (toggleable; both voice and beep options).
- **15.00–17.00 → +2**, applied automatically and shown on the solve.
- **>17.00 → DNF**, applied automatically.
- The whole screen participates in the countdown — see §6.2. You will *feel* 12 seconds coming.
- Inspection auto-disabled for BLD/FMC, toggleable per-event otherwise.

### 3.3 Start/stop mechanics

- Hold-to-arm with a configurable threshold (default 300ms, cstimer-compatible 0/300/500 presets).
- Colour states: idle → red (holding, not ready) → green (ready) → running.
- Spacebar, any key, touch, and (roadmap) Stackmat + Bluetooth smart cubes.
- **Multiphase timing**: optional — tap space mid-solve to record splits (cross / F2L / OLL / PLL), then get per-phase averages. Genuinely useful and almost nobody implements it well.
- Anti-misfire: a solve under a configurable threshold (default 500ms) prompts "discard?" instead of silently recording a 0.14.

## 4. Stats

Every metric computed incrementally (rolling window) so a 10,000-solve session stays instant.

**Core**: current/best `ao5`, `ao12`, `ao50`, `ao100`, `ao1000`, `mo3`, session mean, best, worst, count, standard deviation, DNF rate, +2 rate.

WCA-correct averages: trim best and worst, DNFs count as worst, 2+ DNFs in a window → DNF average. This is a detail cstimer gets right and most clones get wrong.

**Visualizations** (all hand-drawn animated SVG):

1. **Trend chart** — solve times over the session with an overlaid rolling ao5 and ao12 line, a horizontal PB line, and hover-scrub that snaps to a solve and shows its scramble.
2. **Distribution histogram** — where your times actually cluster, with mean and median markers.
3. **Consistency dial** — a radial gauge from your standard deviation, animated on update.
4. **Solve heatmap** — GitHub-contributions-style calendar of solve volume per day, with a streak counter.
5. **Per-case bars** — trainer mode: every case ranked by average, worst in red.
6. **Session comparison** — overlay two sessions' trend lines.

**Session management**: named sessions, per-event sessions, rename/duplicate/delete, drag to reorder,
"move solves to session", and a session summary card you can export as a PNG image to post.

## 5. Customization engine

The core idea: **the entire visual design is a set of CSS custom properties.** The settings panel writes
to those variables live. Nothing rebuilds, nothing reloads, changes are visible as you drag the slider.

**Theme tokens**: background, surface, surface-elevated, border, text, text-muted, accent, accent-2,
success, warning, danger, timer-idle, timer-holding, timer-ready, timer-running, plus radius, blur
strength, border weight, shadow depth.

**What the user can change**:

- **Background**: solid, gradient (with an angle/stop editor), **their own uploaded image**, **their own video loop**, or one of the built-in **animated WebGL shaders** (aurora, liquid metal, starfield, plasma grid, particle field). Uploaded media is stored in IndexedDB as a blob so it survives reloads and never touches a server.
- Background **blur, dim, saturation, scale** sliders — so any photo can be made readable behind the timer.
- **Timer font** (bundled: Inter, JetBrains Mono, Space Grotesk, Chivo Mono, a 7-segment LED face, plus "use a system font"), size, weight, letter-spacing, and an optional gradient or glow fill on the digits.
- **Layout**: drag panels (scramble / cube / stats / history) to reposition, resize, or hide entirely. A saved layout is part of the theme.
- **Density**: compact / comfortable / spacious.
- **Motion**: full / reduced / off — and it respects `prefers-reduced-motion` by default.
- **Preset themes** shipped: `Nebula` (deep purple glass), `Carbon` (near-black minimal), `Vaporwave`, `Paper` (light, print-like), `Terminal` (green mono), `Speedcube` (WCA sticker colors).
- **Export / import theme as JSON**, plus a shareable theme URL string. Users can trade themes.
- **Cube color scheme editor** — recolor the 3D cube and all sticker diagrams (for stickerless, or a custom scheme).

## 6. The motion design — the "crazy" part

This is where it stops being a cstimer clone. Every one of these is scoped to be performant
(transforms and opacity only, GPU-composited, all disabled under reduced-motion).

### 6.1 Boot

The app assembles itself: background shader fades up, then panels spring in on a stagger from their
edges, then the timer digits count up in a blur-to-sharp reveal. About 700ms, once.

### 6.2 Inspection — the whole screen is the countdown

Not a number in a corner. During inspection:

- A **thin ring of light traces the screen perimeter**, depleting as the 15 seconds burn down.
- The background shader's color temperature **drifts from neutral → amber at 8s → deep red at 12s**, and its motion speeds up as time runs out.
- The digits **breathe** with a pulse that quickens — a subtle, escalating heartbeat.
- At 8s and 12s the whole viewport gives one sharp **pulse-flash** synced with the audio callout.
- Past 15s the frame goes red and a **+2** badge slams in; past 17s it goes to **DNF** with a hard glitch cut.

### 6.3 Solve — Focus Mode

The instant the timer starts, **everything except the digits leaves**: panels slide out and blur, the
background dims and its animation slows to near-stillness, the shader desaturates. You are left with
numbers on a dark field. On stop, everything **springs back in on a stagger** — and the new time card
flies from the timer position into the top of the history list.

### 6.4 The Pace Ghost (my favourite, and I have not seen it anywhere)

An optional razor-thin bar beneath the timer that fills at the rate of **your current PB** (or ao5, your
choice). If your live time is still under that pace, it glows green; the moment you fall behind, it goes
red and stops. You get live, peripheral feedback on whether this solve is going well — without reading
a number mid-solve.

### 6.5 PB celebration

New personal best: a **shockwave ring** expands from the digits, the accent color floods the theme for
about 400ms, confetti in the user's own theme colors, a rising chime, and the time card lands in history
with a gold edge that shimmers once. Tiered — a PB single, a PB ao5, and a PB ao12 each get their own
intensity so it does not get cheap.

### 6.6 The scramble preview is static, on purpose

The cube shows the finished scrambled state instantly — no move-by-move playback. You will
execute the scramble faster than any animation could play it, so watching one is pure delay.
3D and flat-2D views, plus a last-layer-only view that the PLL and OLL trainers switch to
automatically. Every WCA puzzle is supported, not just cubes.

### 6.7 Number motion

Times count up or down to their new values rather than jumping. Stat tiles flip on change. Improved stats
flash green and nudge up; worsened ones flash red and nudge down. Small, but it makes the stats panel
feel alive instead of like a spreadsheet.

### 6.8 Micro-interactions

Magnetic hover on buttons, spring-morphing modals that grow out of the element that opened them,
a Cmd+K command palette that blurs the page behind it, toasts that stack and swipe away, and a
right-click radial menu on solves (+2 / DNF / comment / copy scramble / delete) instead of a boring
dropdown.

## 8. Data model

```ts
Solve {
  id, sessionId, event, scramble, scrambleState,
  timeMs, penalty: 'none' | '+2' | 'DNF',
  phases?: number[],           // multiphase splits
  caseId?: string,             // trainer mode — enables per-case stats
  comment?: string,
  createdAt, tags?: string[]
}

Session { id, name, event, mode, createdAt, order, stats (cached) }

Settings { inspection, holdTime, theme, layout, motion, audio, ... }
```

**Import/export**:

- Export everything as JSON (full backup).
- Export a session as CSV.
- **Import an existing cstimer export** — a parser for cstimer's JSON format so the user's entire
  history comes across on day one. This is the single biggest reason people do not switch timers, so
  it ships in v1.
- Export a session summary as a shareable PNG card.

## 11. Known risks and how they are handled

| Risk | Mitigation |
|---|---|
| Random-state scrambles are CPU-heavy and WASM needs warm-up | Web Worker + pre-generation queue + fallback pool. User never waits. |
| 3D cube tanking framerate on low-end phones | Instanced geometry, capped DPR, auto-downgrade to 2D net on weak devices, pause render when off-screen. |
| Shader background eating battery | Pauses when the tab is hidden, freezes during solves anyway (focus mode), and there is a static-background option. |
| Heavy animation hurting timer accuracy | Timing is timestamp-based, not frame-based — animation jank can never change a recorded time. |
| ZBLL (493 cases) bloating the bundle | Algorithm sets are lazy-loaded per trainer, compressed, cached. |
| Users not wanting to lose their cstimer history | cstimer JSON importer ships in v1. |
| Accessibility vs. heavy motion | `prefers-reduced-motion` respected by default, full keyboard nav, real focus states, ARIA on all controls. |

## 12. Running it

No prerequisite beyond a static file server. `start.bat` launches one with Python and opens
the timer. Node is not required at any point — that was the original plan's only blocker and
the no-build architecture removes it entirely.

## 13. Keyboard shortcuts

Every action worth repeating has a key, because a timer is a keyboard app.

| Group | Keys |
|---|---|
| Timer | hold `Space` to start/stop · `Esc` cancels inspection |
| Last solve | `Delete` remove · `Ctrl+Z` undo · `2` +2 · `D` DNF · `0` clear · `C` comment |
| Scramble | `N` new · `←` `→` step through · `Ctrl+C` copy |
| Go to | `E` event · `M` mode · `S` session · `A` stats · `H` all solves · `T` appearance · `,` settings · `K` cases · `?` shortcut list |
| Palette | `Ctrl+K` or `/` |
| View | `Z` zen · `F` fullscreen · `V` 3D↔2D · `I` inspection on/off |
| Careful | `Ctrl+Shift+Delete` clears the session (with undo) |

Every destructive action has an undo toast. Shortcuts are ignored while typing.

A low-key chip pinned bottom-left: an Instagram glyph and `built by @cubingngagng`, at 50%
opacity, brightening on hover. It fades out entirely during a solve along with the rest of the
